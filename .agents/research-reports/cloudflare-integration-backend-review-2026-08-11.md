## Meta

- Depth: full read of all 20 in-scope files + 7 supporting files (connector factory/registry, validator, encryption service, workspaces/targets/data-adapter services, entities, app.module, plan doc, console category constants)

## Executive Summary
The feature is well-architected: workspace isolation is enforced at every layer, the API token is envelope-encrypted and masked, there is no SSRF surface, and the scheduler lifecycle (remove-before-add, backfill, orphan guard, delete cleanup) mirrors the proven scan-schedule pattern. Two MAJOR issues need fixing before merge: (1) the documented duplicate-target race guard catches `BadRequestException` but the real concurrent race (cron tick vs manual sync) produces a Postgres unique-violation `QueryFailedError` which is not caught — the sync fails with 500 exactly in the scenario the code claims to handle, and the SC-ING-3 test mocks the wrong failure mode; (2) the ingestion layer never refreshes data: subdomain assets' `dnsRecords` are never updated after first insert (`orIgnore` only), and the primary asset merge is a union that retains deleted records forever — a direct deviation from the plan's explicit "REPLACE with newest snapshot" decision, which undermines the core value of a periodic sync. Several MINORs (null `syncSchedule` → 500, generic 500 error bodies hiding CF failure detail, synchronous long-running HTTP sync, non-atomic partial sync) and a list of uncovered risky paths round out the review.

## Test Gaps (risky paths with no coverage)
1. **Real duplicate-race failure mode** — SC-ING-3 (cloudflare.ingestion.spec.ts:179-202) mocks `BadRequestException`; the production race throws `QueryFailedError` 23505. No test simulates two in-flight `createMultipleTargets` against the unique index. This is the "mock makes the test pass vacuously" case.
2. **Page caps** — `MAX_ZONES_PAGES`/`MAX_DNS_RECORDS_PAGES` (connector:361-363, 383-385) have zero tests; a misbehaving `total_pages` response is untested.
3. **Retry-after variants** — no test for HTTP-date, missing header, `retry-after: 0`, or the 60s clamp (connector.spec.ts:268-303 covers only integer seconds).
4. **Non-429 failures** — no test for 5xx (no-retry behavior) or for `success:false` envelope with `result_info` absent; `total_pages ?? 1` fallback (connector:358, 380) untested.
5. **Zone status filter** — the defensive `zone.status !== 'active'` skip (connector:207) is untested.
6. **Staleness policy** — no test asserting what happens to *existing* subdomain `dnsRecords` on re-sync (the orIgnore-only path) or to primary records deleted from Cloudflare (merge keeps them). F2 needs a regression test whichever way it's resolved.
7. **Concurrent syncs** — manual + cron overlap is untested at every level.
8. **toResponse masking/leak** — the DTO spec only asserts `'syncJobId' in dto === false` on the class (integration-schedule.dto.spec.ts:88-91); no test runs the real `toResponse` to assert `apiToken` is masked (`****last4`) and `syncJobId` is absent from the serialized object.
9. **`syncSchedule: null`** — no DTO/service test for null vs undefined (F3).
10. **Partial-failure semantics** — no test that a mid-sync zone failure leaves earlier zones written and `lastRunAt` untouched (it is — runSync:198-201 — but untested).
11. **applySchedule queue failure** — no test that `queue.add` rejection leaves the integration row without a schedule and rethrows (F4).
12. **testIntegration 404 / foreign workspace** — controller spec mocks the service; the service path is untested.

## Positives
- **Tenant isolation**: `getIntegrationById`/`getIntegrationWithDecryptedConfig`/`syncIntegration` are workspace-scoped; the processor guard double-checks workspace on every tick; controller routes carry `@WorkspaceAccess('integration.write')`/`read` (verified via reflector tests).
- **Secrets**: apiToken detected via `ui:widget: password`, envelope-encrypted per-workspace DEK, masked `****last4`; no decrypted config ever serialized.
- **No SSRF surface**: base URL hardcoded, paths fixed, `additionalProperties: false` in the schema — no user input reaches a URL.
- **Fetch layer**: 429 retry-after (capped 60s), 3 attempts, `AbortSignal.timeout(30s)` per request, page caps against token abuse — all tested except the gaps above.
- **Idempotency**: `@Unique(['workspaceId','value'])` + `@Unique(['value','target'])` back `orIgnore`; `seenAssets` per-sync dedupe; punycode kept verbatim (consistent with dnsx/subfinder output); `100::` placeholders and wildcards counted but never materialized; 7-key dnsRecords shape exactly matches built-in subfinder parser (built-in-tools.ts:19-37).
- **Scheduler lifecycle**: remove-before-add, `repeatJobKey` persisted to `syncJobId`, backfill on module init (indexed by the dedicated migration), delete cleans up, orphan guard drops stale jobs, non-cloud syncs rejected at three gates (DTO category check, create/update, runSync).
- **Failure semantics**: `lastRunAt` only on full success; connector errors rethrown (job fails, not swallowed); dry-run never writes DB or `lastRunAt`.
- **Tests**: scenario-ID'd TDD (SC-CONN/ING/SCHED/API/DTO), including DI-metadata regression tests guarding SWC `design:paramtypes` erasure — unusually thoughtful; SC-CONN-12 regression-guards `TargetSource.CLOUDFLARE` landing in the 5th arg.
- **Migrations**: NOT NULL DEFAULT for backfill-safe columns; dedicated index matches the backfill query; source backfill explicit.

## Verdict
**mergeable-with-fixes** — F1 (race guard catches the wrong error type) and F2 (no data refresh; plan-deviation to union-merge) should be fixed or explicitly accepted by the product owner before merge; everything else is MINOR/NIT.
